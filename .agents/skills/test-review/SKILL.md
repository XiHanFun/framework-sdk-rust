# Rust SDK 测试审查

对每个测试给出「保留、改写、合并或删除」的结论，并指出它保护的规范行为或公开不变量。

- 保留：缺陷复发时会失败，覆盖规范要求的行为、错误码与消息键、核对顺序、取消与截止时间、容量或平台差异。
- 改写：只断言内部函数被调用、依赖私有布局、用长时间真实等待代替确定的会合、没有失败路径。
- 合并：与相邻用例输入和断言等价，不能提供额外定位。
- 删除：不可能失败、只验证常量或标准库本身，或已被向量回放完整覆盖。

## Rust SDK 专项

- 向量回放要逐个用例断言并在失败消息里带上用例名；不能因向量字段缺失而静默跳过用例。
- `tests/conformance_vectors.rs` 的 `REPLAYED` 要与真正读取该向量的测试一致，行尾注释写对测试位置。
- 黑盒运行器测试不能静默变绿：缺 Go 默认失败，只有 `XIHAN_CONFORMANCE_REQUIRED=0` 才提前返回；用例名单与运行器一致、每个都通过且没有跳过。
- 截止时间与取消的测试用确定的触发（例如测试专用的立即触发），不靠与墙上时钟赛跑。
- 插件运行时的测试区分平台，`#[cfg(unix)]` / `#[cfg(windows)]` 的分支各自有断言。
- 没有开发依赖：异步测试用 `tests/common` 的执行器，不为测试引入 tokio 之外的新依赖（tokio 只在 feature `plugin` 下）。

输出按风险排序，附文件与行号。除非用户要求运行，否则只做静态审查；不通过删测试或放宽门禁解决生产缺陷。
